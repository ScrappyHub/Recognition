## What Recognition can do today

**As a browser**, on Windows, self-contained (no Anthropic/Cursor-style cloud
dependency): multi-tab browsing with favicons and Opera-style sleeping tabs
(hidden tabs suspended to free memory), an omnibox with suggestions drawn from
its own history and bookmarks, find-in-page, per-tab zoom, standard keyboard
shortcuts, a home button with a configurable home page, private/incognito tabs
(ephemeral profile, nothing persisted, erased on close), Brave-style tracker/ad
blocking with a per-site shield counter, HTTPS-first navigation, no autofill
and no telemetry, governed Chromium extension loading from an explicit
allowlist, and passkey/WebAuthn sign-in (Windows Hello or a security key) on
HTTPS origins with no passwords stored by the browser.

**As a self-owned VPN**: an on/off toggle, 14 exit slots (US East/West,
Canada, UK, EU, Germany, Netherlands, Switzerland, Singapore, Japan,
Australia, Tor-local, and two custom HTTP/SOCKS slots), auto-optimize by
latency, and a toolbar indicator with three honest states — on, off, or
"exit unreachable, running direct" (added this week so a dead or placeholder
exit can never silently break browsing). Incognito tabs force the VPN on and
probe the exit before opening rather than opening unprotected. Recognition
runs no exit servers of its own — every location is a slot for the user's own
proxy, WireGuard config, or Tor; this is a stated design choice (self-owned,
no vendor lock), not a shortfall.

**As a governed instrument** — the part that distinguishes it from an
ordinary browser: a fail-closed locked-startup gate that verifies identity,
policy, trust root, and a signed SoftwareID (SHA-256 of the running binary,
Ed25519-signed, checked against a pinned trust root) before the web view ever
opens — a modified binary is refused, not silently run. Five independent
append-only, hash-chained, tamper-evident ledgers, each with its own
negative-vector selftest (tamper, reorder, forge, missing/deleted record) and
each encrypted at rest with Windows DPAPI (bound to the Windows account, no
password prompt): browsing history, bookmarks, downloads, a general
action-receipt ledger covering every meaningful action (navigate, download,
bookmark, VPN change, history clear, session export), and a cookie-governance
ledger (cookie name+value stored only as a SHA-256, domain kept in the action
label). The identity layer stores only non-secret hash outputs in the open;
the one reproducible secret is DPAPI-sealed, never written in cleartext, with
automatic migration for any older identity file that still had it inline.
Every session can be exported as a single verifiable evidence packet carrying
all of this — history, tabs, VPN state, action-receipt chain head, and
cookie-receipt chain head — so a reviewer can check the browser's own account
of what happened, not just take Recognition's word for it.

**Formally**: two TLA+/TLC models, checked in CI on every push — Soundness
and TamperEvidence for the evidence chain, and FailClosed for the locked
startup gate.

**As a shippable product**: a self-contained win-x64 build, a per-user
installer with shortcuts and an uninstaller, an optional Inno Setup
`.exe`, and a strict release gate (packet law + all 16 prove-all components
+ browser build) that has to go fully green before anything ships — enforced
both locally and in GitHub Actions on every push to `main`.

## Honest gaps (unchanged by this audit, still real)

- No full per-origin network policy engine — tracker/ad blocking is
  request-level, not a complete policy layer.
- No password engine (deliberate — no password autosave by design).
- No certificate manager, sync engine, or auto-updater.
- No encrypted cookies *engine replacement* — Chromium's own OS-level cookie
  encryption is the actual storage; Recognition's ledger is a governance
  witness on top of it, not a reimplementation.
- The `C:\dev\_ecosystem` canon files CLAUDE.md asks to be read
  (`SERVICE_MAP`, `SHARED_INVARIANTS`, `AGENT_POLICY`) are still not present
  in this environment — this scoreboard reflects the in-repo handoff only,
  as noted since the last audit.
- Crypto-composition formal proofs (beyond the two TLA+ models that exist)
  are still just planned, not built.
